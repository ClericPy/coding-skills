# 角色工厂（role-factory）

把「一句话建个 Bot」变成可复核的四步：查重 → 备份 → 裁剪 → 交总管执行。

## 何时用

- 要建 Bot、要改某个 Bot 的角色指令、要按分组造一套角色、要搭一个开发团队、要按模板生成角色指令。
- 不用：代码审查、功能实现、跑测试、一般问答 —— 那些直接做，别加载本技能。

## 两种模式

- **产出模式（默认，任何 agent 可用）**：只交付「可直接粘贴的 instructions + 建议 name / role / section / model + 来源行」，不要求调用方有建 Bot 权限，也不要求任何核对。
- **执行模式（调用方是 Main Bot）**：在上面基础上真正落地，并可选用 `list_bots` 核对一次——这是建议，不是门。

## 权力边界

- **只有 Main Bot 能 `create_bot` / `update_bot`**。本技能产出的是**可直接粘贴的 instructions**，自己不建、不自己改；执行模式由 Main Bot 落地。
- 不替用户决定建不建、建几个、用哪个模型：给建议并标【推荐】，等用户点头。
- 覆盖旧 instructions 不可逆：先备份、先说明「会替换全部指令」、拿到确认才动。

## 四步流程

### 1 查重

`list_bots` 拉全量：同名、同 section、职责重叠都要报出来。已有同名时问「覆盖 / 换名新建 / 跳过」，不默认覆盖。

### 2 备份

覆盖前把旧 instructions 原文存到系统临时目录（`role-<name>-<时间戳>.md`），并在回复里给出路径，便于回滚。

### 3 裁剪

按项目只改三处：项目路径与仓库名、专属边界（本团队禁止的动作）、模型与 effort。**只改这三处，不动角色边界**。

### 4 交总管执行

给出 create/update 参数（name / role / section / instructions / model / effort），由 Main Bot 调工具落地。本技能不调工具。

## 六个角色（完整提示词见 references/roles 目录）

- **总管**：接单、分派、验收、汇总；不写代码，只核证据。
- **领域专家**：问清需求，写判定可判真假的 Spec。
- **架构**：方案与选型、开工前的架构评审。
- **开发运维**：实现、修 Bug、自配环境与门禁。
- **评审测试**：独立审查、对抗挑刺，只审不改。
- **助理（可选）**：总管的下延之手，只接总管指派的零碎活。

最小例子：用户说「给我建个开发团队」→ `list_bots` 查重 → 选 总管 + 领域专家 + 开发运维（需要独立审查再加 评审测试）→ 每份 instructions 取 `references/roles/<角色>.md` 原文 → 按项目改路径与门禁 → 请 Main Bot 执行 `create_bot`。

## 产物契约（不许省）

每份生成或更新的 instructions，**末尾必须附一行来源标注**：

`来源：role-factory v<版本> · references/roles/<角色>.md`

用途：模板改版后能反查某个 Bot 是按哪一版造的，据此判断要不要重建。调用方明确说不要时可以省，但交付里要写「已按要求省略来源行」；除此之外缺即不合格。

## 交付格式

- 每份 instructions 单独一个代码块，块前写目标 Bot 名与建议的 role / section / model。
- 结尾列出：查重结论、备份路径、裁剪了哪几处、待决项；未做核对时写「未核对（产出模式）」。

## 细节

- 查重口径、覆盖前确认、裁剪清单、create/update 参数、创建后自检 → `references/flow.md`
- 六份角色原文 → `references/roles/总管.md`、`领域专家.md`、`架构.md`、`开发运维.md`、`评审测试.md`、`助理.md`；改角色内容只改这些文件，再跑本技能自带的 `scripts/build_roles.py` 重新生成根目录 `TEMPLATE-roles.md`。
