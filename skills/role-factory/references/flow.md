# 落地流程（role-factory）

## 0 两种模式

- **产出模式（默认，任何 agent 可用）**：只交付「可直接粘贴的 instructions + 建议 name / role / section / model + 来源行」。不要求调用方有建 Bot 权限，也不要求任何核对。
- **执行模式（调用方是 Main Bot）**：在上面基础上真正落地，可选做第 5 步的核对。

## 1 查重

- `list_bots` 拉全量，报三类：同名、同 section、职责与其他 Bot 重叠。
- 已有同名 → 问「覆盖 / 换名新建 / 跳过」，默认跳过，不默认覆盖。
- 同 section 已有人 → 说明职责差异，问是并行还是合并。

## 2 覆盖前三件事

1. **备份**：旧 instructions 原文存成 `role-<name>-<时间戳>.md` 放系统临时目录，回复里给路径。
2. **说明**：明确写「覆盖会替换全部指令，不是追加」。
3. **确认**：用户从「覆盖 / 新建 / 跳过」里选一个，没选不动。

## 3 裁剪清单

只改这三处：

- 项目路径与仓库名（把模板里的泛称换成真实仓库）。
- 专属边界：本团队禁止的动作、必跑的门禁命令、发布面约束。
- 模型与 effort（按任务复杂度给建议）。

不动：角色职责、硬边界编号、检查清单结构。

## 4 create/update 参数

| 参数 | 怎么给 |
| --- | --- |
| `name` | 英文短名，全团队唯一；中文名放 `role` 或用作显示名 |
| `role` | 二到四字标签，如「总管」「开发」 |
| `section` | 分组名；同项目团队放同一 section |
| `instructions` | 整段原文（含末尾来源行），不做改写 |
| `model` / `effort` | 给建议值并说明理由，不替用户定 |

新建用 `create_bot`；改已有 Bot 用 `update_bot`（`bot` + 新 `instructions`）。

## 5 产出自检（建议，不是门）

- 调用方本身有建/改权限时，**建议**用 `list_bots` 核对 name / role / section / model，并确认 instructions 末尾有来源行。
- **核对不上如实报一句即可**，不算失败、不阻塞交付。
- 没有权限或不需要核对 → 跳过，交付里写「未核对（产出模式）」。

## 6 来源行

- 默认附：`来源：role-factory v<版本> · references/roles/<角色>.md`
- 调用方明确说不要 → 可以省，但交付里要写「已按要求省略来源行」。
- 这一行是给未来反查用的：模板改版后能判断某个 Bot 是按哪一版造的。
