# 三档定级锚点

定级看**后果**，不看改动大小。同一处代码在正确性与可观测性上各有一条问题，就报两条，不要合并成一条模糊描述。

## Blocker（阻塞合入）

必须满足其一：

- **正确性**：逻辑错误、边界错误、会导致错误结果的实现。
- **安全性**：输入未校验导致的注入 / 越权；敏感信息（Token / 密码）写入日志；密钥硬编码。
- **数据损坏**：不可逆的数据写入、迁移或删除缺少保护。
- **线上兼容破坏**：已发布的协议、数据格式或行为被改变，且没有迁移 / 灰发 / 回滚路径。
- **Spec 硬性违背**：与 Spec 条款直接冲突，且非文档过期所致。
- **并发致命**：协程 / 主线程被阻塞；资源泄漏在正常路径上必然发生。

## Major（应当修复）

- **架构与设计**：破坏 SOLID、反向依赖、破坏既有设计模式、重复造轮子。
- **过度设计**：为假想需求引入的抽象或配置（YAGNI）。
- **健壮性**：异常捕获过宽或吞异常；边界条件未定义；资源生命周期不闭环。
- **并发与任务生命周期**：后台任务逃逸出所有者生命周期、无法取消或失败不可观测。
- **性能**：热路径上的 N+1、循环内 IO、可避免的内存放大（需给出热路径与数据规模两项证据）。
- **依赖与配置**：依赖清单与锁文件漂移、版本未固定、CI 权限过宽、密钥进入构建产物。
- **可观测性**：核心业务路径或异常捕获处缺少日志 / 追踪点。
- **测试**：本次改动缺少对应测试，或测试未全部通过。

## Minor（可选建议）

- **可读性**：命名不清晰、结构可简化。
- **注释**：冗余注释、注释与代码不一致、过时注释。
- **轻微重复**：无伤大雅的重复代码、可提取的命名常量。
- **性能微调**：缺一项性能证据、收益有限的优化。
- **不确定项**：有真实风险但证据链不完整、无法定位到具体行或 Spec 条款的怀疑 —— **必须标注不确定性**，不得伪装成结论。

## 不确定时不许丢的类别（受保护主题）

以下五类问题的代价是**静默破坏**：线上悄悄失效、并发下偶发、跨文件契约断裂。它们**不适用「证据不全就丢弃」**，处理方式是降档并明写不确定，而不是删掉：

1. **内存安全**：越界、释放后使用、空指针解引用、缓冲区长度。
2. **并发安全**：锁与锁模式、原子性、数据竞争、同步约定的失效。
3. **声明与定义一致性**：`static` 与非 `static`、声明与实现不符、接口与实现签名漂移。
4. **行为与兼容性变更**：旧版本有、新版本没了的行为、字段、状态或默认值；错误路径改变；计数更新时机挪位。
5. **收下却未使用的参数**：调用方按旧语义传参，函数却已不再使用它。

判定口径：这五类只要**能指出具体代码位置**，就以「不确定项」进 Minor（或按后果定更高档位）并写明待确认点；不得因为「不够确定」而不写进报告。

## 两条反向纪律

- **低价值 ≠ 错误**：风格、命名、注释类问题若属实，只是降档到 Minor，不能因为「价值低」而删除。真正该丢的只有两种情况：与 diff 事实相矛盾，或给不出任何证据链。
- **不可验证 ≠ 错误**：核实不了的事实，要么标成不确定项，要么不写；**不得**把核实不了的心虚改写成确定口吻的结论。

## 正反例

**该报（Blocker）**

> **`api/handler.py:88`** 未校验 `user_id` 即拼接进 SQL，存在注入风险。依据：「输入校验」Spec 条款 + 该行直接字符串拼接。
> 修复：`cur.execute("SELECT * FROM t WHERE id = %s", (user_id,))`

**该报（Blocker，兼容性）**

> **`proto/order.proto:31`** 复用已下线字段的编号，旧客户端会把它解析成原字段类型，静默读出错误数据。依据：该编号在上一版已发布 + 协议只允许保留编号不复用。
> 修复：改用未使用的编号，并把原编号与名称一并标记为 reserved。

**不该报（噪点，必须丢弃）**

> ~~「这个模块的异常处理感觉不够健壮，建议整体重构」~~
> 丢弃理由：无具体代码行、给不出证据链、无法定位到 Spec 条款。属推测，违反 ≥80% 置信度门禁。

**该报（Major，可观测性）**

> **`worker/consumer.py:57`** 消息消费失败仅 `pass`，无日志无追踪，线上故障无法定位。
> 修复：`except ParseError as exc: logger.warning("parse failed", extra={"msg_id": msg_id}, exc_info=exc)`

**该报（Major，性能）**

> **`service/report.py:64`** 循环体内逐条 `session.get(Order, oid)`，列表长度随订单数线性增长；本次改动把批量查询换成了逐条查询。
> 修复：先收集 `oid` 列表，用一次 `select(Order).where(Order.id.in_(oids))` 取回后建字典。
