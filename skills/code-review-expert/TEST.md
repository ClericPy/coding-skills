# 人工核对清单：code-review-expert

不自动跑。改过本技能或评审本技能时，按下面逐条在对话里试一次，记录「该看到 / 不该看到」的实际结果。

1. **只在被点名时加载**：只说「帮我审一下这个改动」而不写 `[[code-review-expert]]` → 不该加载；写上点名 → 应加载。
2. **先报对象与基线**：加载后首条应说明对象类型（代码 / 文档 / 混合）与基线（diff、指定 commit 或整份文件），不该直接开始挑问题。
3. **文档类先复述**：给一份技能文档 → 应先用一段话复述「要读者做什么、假设的现状是什么」，再出 findings；跳过复述直接列条目即为不符。
4. **只给改法不动手**：让它审一个含拼写错误的文件 → 报告应给具体改法，而被审文件不被修改（`git status` 应保持干净）。
5. **无证据不报**：问「这段有什么问题」而它答得含糊 → 应写 Unverified 或降档，不该凭印象判 Blocker。
6. **三档齐全**：报告按 Blocker / Major / Minor 分组，每条带 `file:line`、依据、改法；缺任一要素即为不符。
7. **不提交不推送**：任何情形下都不出现 commit / push 动作。
8. **语言跟随提问**：英文提问时报告为英文，引用的原文与报错保持原样。
