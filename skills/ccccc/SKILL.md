回顾最近 5 次提交信息，学习提交格式：

1. 公司要求的提交格式非常严格，要注意冒号左边就那几个特定单词、空格空行都要一一对应。（fix:/feat:/docs:/test: 等）
2. 如果模版里有 ID 类的字段（例如 JIRA-ID），用户没有指定，就用最近一次的那个 ID，绝不凭空构造；其他字段不确定也不要凭空捏造，只要其他几次提交都用了那个值，就继续复用那个值
3. 要自动根据上下文判断现在准备提交的是在 worktree 里还是正常分支上
4. 要先告知用户改动行数情况，要打印告诉用户提交信息填的什么
5. 注意 description 不要太长，200 字以内，绝对不要换行，多条可以用；隔开
6. 用户允许的时候可以创建提交（总结当前改动），但绝对不要 push
7. 单次 commit 不超过 500 行（新增），若超过则按正确方式分多次提交
8. 某一次修改如果行数很少而且相关性还可以，不必拆分太细分的提交导致提交历史太冗余
9. 除了提交信息里有的那些行，绝对不要自己加新行放太多冗余信息，可以在描述里单行描述代替新增行
